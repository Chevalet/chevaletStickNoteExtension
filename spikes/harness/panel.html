chevaletNote · phase 0 spikes

Every result here is evidence against a specific design decision in the plan. Anything that fails changes the design — that is the point of running these before writing product code. Run the whole sheet on Firefox release and ESR.

0 · Access

Firefox MV3 does not grant host permissions at install. This button is the real onboarding flow the product will use. Without it, nothing can be injected anywhere.

R1 · Does a content-script beforeunload actually prompt on tab close?

Pick a tab below, press Inject probe, click once inside that page (sticky activation is required), then Arm guard and work the matrix. Record each answer — the whole close-confirmation feature rests on row 1.

  1. Armed + page interacted → close the tab. Dialog? If no, isolated-world cancellation is ignored and world:"MAIN" becomes mandatory.
  2. Armed + page never interacted (inject, do not click, arm from here) → close. Expect no dialog, confirming the sticky-activation rule.
  3. Arm three tabs, close the whole window. How many dialogs, and does Firefox focus each tab in turn? This sizes the guard budget.
  4. Armed, then quit with Ctrl+Shift+Q. Dialogs? After choosing Stay, does session restore still work?
  5. Armed → Close via tabs.remove() below. Expect the guard to be bypassed.
  6. Set dom.disable_beforeunload = true in about:config → expect suppression.
  7. Discard the tab in about:unloads, then close it. Expect silence.
  8. bfcache: time a back-navigation with the guard armed vs disarmed.

R5a · Tab identity — does sessions.setTabValue survive everything?

A key is minted on each tab's first load. Do these and re-read the table each time: restart with session restore · Ctrl+Shift+T · duplicate a tab (does the clone carry the same key?) · drag a tab to a new window · a container tab · a private window · discard via about:unloads · kill the Firefox process 3 s after a fresh tab loads.

R5a · Recovery — restore and reattach

Restore uses Firefox's own undo stack (shallow, ~10–25 entries). Reopen + reattach is the product's own path: recreate the tab and hand it back its old key. That one has no depth limit, and this is where we prove it.
